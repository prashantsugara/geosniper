# Unity Relay duels

Internet HOST/JOIN now uses Unity Multiplayer Services 2.3.3, anonymous Authentication, and Unity Transport with DTLS Relay. Hosts allocate one guest slot; only after the transport binds successfully does the UI expose a 10-digit room code. Guests can paste a whole invite or enter the 10-digit code (including leading zeros). Direct IP and subnet codes are not accepted by the internet join action.

The existing session nonce, reliable packet acknowledgements, map streaming, score authority and reconnect protocol run over the new transport. Host/guest share the exact selected map. UDP LAN helpers remain available for development but the normal UI no longer discovers or advertises LAN rooms. No Google IP lookup remains.

Async setup uses request timeouts and room generations: closing the room, switching to the Join tab or destroying the network invalidates pending startup results and disposes the transport. Transport allocation expiry ends the room with a clear retry message. Practice stays offline.

## Dashboard setup

The main project's linked cloud project is 6f5b6ca7-39ab-4a34-9f08-4a1c7779fae8. In Unity Dashboard, verify the correct project, enable Relay, and enable Anonymous sign-in under Authentication. Use the same project/environment for both builds. No server secret belongs in the client.

## Validation

Runtime and editor code compile against the resolved SDK. RelayDuelChecks.Run validates code normalization, pasted invites, invalid codes, rejection of direct IPs, allocation loading state, cancellation, two-peer Unity Transport handshake and byte-exact reliable transfer of a 64 KiB synthetic map over local loopback.

RelayDuelChecks.RunLive is a separate live smoke test. It creates a temporary Relay allocation and sends randomly generated bytes between two fixture peers, then closes their drivers. It does not send a real player map, GPS location or user files. Live execution is pending user approval after automatic approval review rejected the external service test. These local checks do not verify dashboard activation, live DTLS reachability or cross-device Android connectivity.

On two release Android devices, host a room on Wi-Fi and join its code on mobile data. Confirm the shared map, movement, shooting, scoring and reconnect. Capture [DuelRelay] errors for service setup failures. In the Unity Editor, opening the actual project resolves the new manifest dependency; the isolated validation project has already resolved and compiled it.

References: [Relay flow](https://docs.unity.com/en-us/mps-sdk/advanced-config/allocating-binding-joining), [Relay configuration](https://docs.unity.com/en-us/mps-sdk/tutorials/relay-and-ngo).


Numeric codes reversibly encode the six-character base-36 Relay code as a zero-padded decimal number. Old R-prefixed and raw alphanumeric codes remain accepted. No room lookup service is required.
